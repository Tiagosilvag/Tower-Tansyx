# Kanban do Tower Tansyx — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Quadros Kanban (um Geral e um por projeto) no Tower Tansyx, guardados no SQLite, editáveis pela página e por agentes (API local + comando), com autoria do usuário e a marca "via agente".

**Architecture:** Nova migração e `server/kanban/store.ts` (regras e transações), `server/kanban/http.ts` (rotas `/api/kanban/*` ligadas em `server/http/app.ts` como as de usuários), um comando `npm run kanban` para os agentes e um painel em tela cheia no cliente (estante retrátil + quadro + cartão), aberto por um botão da barra, no mesmo padrão lazy do "Meu dia".

**Tech Stack:** Node >=22.13 (`node:sqlite` pela camada `server/db/db.ts`), TypeScript, vitest, cliente em TS puro (`client/src/ui/*`, CSS em `styles.css`).

**Spec:** `docs/superpowers/specs/2026-10-29-kanban-design.md` (mockups: https://claude.ai/artifact/11oyzJc3fLaBt9yU18Ht69). Leia a spec inteira: ela fixa o modelo, a API e as decisões abaixo.

## Global Constraints

- Servidor sem dependências de runtime; banco só por `server/db/db.ts`; **nunca editar migrações já publicadas**: acrescentar uma (o teste de `db.test.ts` usa `MIGRATIONS.length`).
- Todo texto visível passa por `tr('texto em PT')` e entra em `shared/locales/{en,es,fr}.ts` (`npm run i18n:check`); toda mudança visível entra em "Não lançado" do `CHANGELOG.md`.
- Não tocar em `shared/world/` nem `server/world/`.
- Colunas fixas, nesta ordem: `ideias`, `a_fazer`, `fazendo`, `feito`. Prioridades: `alta`, `media`, `baixa`. `via`: `user` | `agent`.
- Limites: título obrigatório até 200 caracteres; descrição até 5000; nome de projeto até 60 (único sem diferenciar maiúsculas, e não pode ser "Geral"); comentário até 2000. Erros em português via `tr()`.
- O Geral existe sempre (criado pela migração), não se renomeia nem se remove. Etiqueta de projeto só em cartão do Geral e só aponta para quadro `project`.
- Autor: porta remota = usuário da sessão, sempre, e `as`/`X-Habblaud-Via` são ignorados; porta local com `X-Habblaud-Via: agent` = `as` validado contra os usuários (ausente ou desconhecido = sem usuário), `via` `agent`; porta local sem o cabeçalho = sem usuário, `via` `user`.
- Remover usuário não apaga cartões nem histórico: referências viram `NULL` e o nome fica gravado no evento.
- O Kanban nunca abre caminho ao computador: as rotas só leem e escrevem no banco. Nada de usuário vai para texto entregue a agentes.
- Respostas JSON com `Cache-Control: no-store`. Conteúdo de cartão no cliente entra sempre como texto (`textContent`), nunca HTML.
- Texto de cartão e descrição em fonte do sistema; só rótulos e títulos de painel usam Pixelify Sans (regra de `styles.css`).

## Review Focus

1. Sessão remota logada que manda `as: "ansysar"` e o cabeçalho de agente continua com o **autor da sessão** e `via` `user` (Tarefa 2).
2. `as` com usuário que não existe, ou ausente, grava autor vazio e `via` `agent`, sem erro 4xx (Tarefa 2).
3. Remover um usuário mantém os cartões dele e o histórico, com o nome gravado no evento (Tarefa 1).
4. Mover cartão para quadro inexistente dá 404 e deixa posições e colunas intactas; reordenar nunca deixa posições repetidas ou com buraco (Tarefa 1).
5. Título ou descrição com `<img src=x onerror=...>` aparece como texto no quadro e no diálogo (Tarefa 5).
